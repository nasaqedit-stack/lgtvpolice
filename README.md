# Offline-First Digital Signage

منصة إدارة وتشغيل شاشات رقمية بواجهة عربية RTL. صُمّمت لتستبدل تحديث USB بالتزامن إلى مشغل ويب مستقل: ينزّل ملفات العرض، يتحقق منها، ويحفظها على الجهاز قبل تشغيلها. **لا يستخدم مشغل التلفاز روابط الفيديو المباشرة أثناء العرض المعتاد.**

> **مهم بخصوص LG:** لم يتوفر تلفاز LG مادي أو مشروع Supabase/Vercel لهذه الجلسة؛ لذلك لم يُدّعَ اختبار توافق طراز/إصدار webOS بعينه أو تشغيل نشر إنتاجي. يجب إجراء اختبار تأهيل على الطراز المستهدف قبل النشر. تعليمات الاختبار في [دليل التلفاز](docs/TV-SETUP.md).

## البنية

- **واجهة الإدارة وواجهات API:** Next.js App Router + TypeScript. استضافة متوافقة مع Vercel.
- **قاعدة البيانات والمصادقة:** Supabase PostgreSQL وSupabase Auth، مع سياسات RLS. كل عمليات الإدارة وعمليات الشاشة تمر عبر Route Handlers خادمية؛ لا يوجد مفتاح خدمة في المتصفح.
- **الوسائط:** Supabase Storage الخاص عبر واجهة S3 المتوافقة. الملفات لا تحفظ في Git ولا في نظام ملفات التطبيق. رفع متعدد الأجزاء بحجم 8 MiB للجزء وروابط موقعة قصيرة العمر. الحد الحالي 2 GiB لكل ملف.
- **مشغل التلفاز:** مسار `/player` عام بلا تسجيل دخول إداري. بيانات اعتماد الشاشة فقط تحفظ في IndexedDB بعد الاقتران.
- **التشغيل أولاً (PLAYBACK > CACHE > SYNC):** يبدأ المشغل من البيان المحلي والوسائط المخزنة فوراً بلا انتظار أي طلب شبكة، ثم يزامن في الخلفية. لا يوقف انقطاع الإنترنت أو فشل البيان أو مهل API العرضَ المخزّناً، ولا يستبدل محتوى يعمل بشاشة خطأ، وتبقى المزامنة غير مرئية تماماً أثناء اللعب. التفعيل ذري، وجمع المهملات يحمي الوسائط المعروضة، وأي إخفاق في المزامنة يُسجَّل ويُعاد لاحقاً بتراجع أسّي.
- **تخزين اللاعب:** IndexedDB هي مخزن الملفات الأساسي: الأجزاء الثابتة تُحفظ كـ `Blob` في مخزن `parts`، والبيانات الوصفية/قائمة التشغيل/الاعتماد في مخازن منفصلة. يجمع المشغل الأجزاء كـ `Blob` محلي عند العرض. يطلب `navigator.storage.persist()` حيث يدعمه المتصفح. Service Worker/Cache Storage يحتفظان بواجهة اللاعب وحزم JavaScript/CSS فقط؛ لا تُخزن ملفات الفيديو في Cache Storage أو `localStorage` أو ذاكرة التشغيل كمصدر دائم.
- **نزاهة وأمان التنزيل:** ملفات TV تُنزّل بطلبات HTTP Range (4 MiB لكل نطاق)، مع استئناف للأجزاء المحفوظة عند الانقطاع. تُحسب SHA-256 محلياً على الأجزاء قبل اعتماد الملف. اختلاف الحجم/البصمة يمنع تفعيل القائمة الجديدة. إذا تعذّر على متصفح التلفاز استعمال الرابط الموقّع (CORS مقيّد، متصفح webOS قديم، توقيع منتهٍ، أو مضيف محجوب) يكمل المشغل التنزيل من مسار التطبيق نفسه `/api/player/media/<mediaId>`؛ الخادم يتحقق من اعتماد الشاشة ومن البيان المنشور في كل طلب ويبقي دلو التخزين خاصاً. روابط S3 الموقّعة تُنشأ بدون معاملات checksum الخاصة بـ AWS SDK.
- **توجيه المحتوى للشاشة:** البيان يضم القائمة المعيّنة صراحةً أو قوائم الجداول المفعّلة. الشاشة المقترنة التي لا تعيين لها ولا جدولة تتبع أحدث قائمة منشورة، فيكفي النشر ليصل المحتوى إلى التلفاز؛ التعيين الصريح أو الجدولة يتقدّمان دائماً على هذا الاحتياط. لا تُضمّن المسودات غير المنشورة أبداً.
- **تحديث ذري:** يبقى مؤشر manifest الفعّال على النسخة القديمة حتى اكتمال كل الملفات وفحصها؛ بعدها يتغير المؤشر داخل معاملة IndexedDB واحدة. التنظيف يحذف الملفات التي لا تشير إليها النسخة النشطة (بما فيها كل قوائم الجدولة) فقط بعد التفعيل.
- **التزامن:** تحقق manifest/heartbeat كل 60 ثانية تقريباً. يستخدم manifest إصداراً وETag؛ إذا لم يتغير، لا تنزل ملفات. روابط الوسائط الموقعة تُطلب فقط للملفات الناقصة/المتغيرة.
- **الجدولة:** تُحمّل إعدادات كل الجداول والقوائم إلى manifest محلي. التبديل يتم بساعة الجهاز حسب IANA timezone، الافتراضي `Asia/Riyadh`؛ لا يحتاج الشبكة.

## الصيغ المدعومة

- الصور: JPEG/JPG وPNG وWebP.
- الفيديو: حاوية MP4؛ الصيغة الموصى بها H.264 للفيديو وAAC للصوت. مدة الفيديو تُقرأ من metadata في المتصفح ويعتمد الانتقال على حدث نهاية الفيديو الفعلي، والتكرار خيار لكل عنصر.
- لا يوجد transcoding أو فحص خادمي كامل للـ codec. اختبار `canPlayType` في متصفح الإدارة تحذيري فقط ولا يثبت توافق التلفاز. ملفات MP4 بترميز غير مدعوم تُظهر تحذيراً قبل النشر. **SVG غير مفعّل في هذا الإصدار** لعدم إدخال SVG غير منقّى؛ صدّر إلى PNG/WebP.
- العرض يحافظ على نسبة الأبعاد باستخدام `object-fit: contain`. التشغيل التلقائي للفيديو صامت لتوافق سياسات المتصفح.

## متطلبات الإعداد والإنتاج

راجع [دليل إعداد الإدارة والنشر](docs/ADMIN-SETUP.md) و[دليل التلفاز](docs/TV-SETUP.md). باختصار:

1. أنشئ مشروع Supabase وفعّل Auth.
2. طبّق `supabase/migrations/20261007000000_initial.sql` باستخدام Supabase CLI أو SQL Editor. تنشئ الهجرة الجداول وRLS والدوال ودلو `signage-media` الخاص.
3. أنشئ مفاتيح S3 متوافقة في إعدادات Storage. لا تضعها في متغير `NEXT_PUBLIC_*`.
4. أنشئ مستخدم Auth ثم رقّ دوره إلى `admin` كما في دليل الإعداد.
5. انسخ `.env.example` إلى `.env.local` واملأ القيم، ثم اختبر `npm run build`.
6. استورد المشروع في Vercel وأضف متغيرات الإنتاج. إعداد `vercel.json` يشغّل مهمة تنظيف يومية للجلسات المنتهية ونبضات الشاشات القديمة؛ أضف `CRON_SECRET`.
7. اضبط Site URL وRedirect URLs في Supabase على أصل الإنتاج، واختبر CORS لطلبات S3 الموقعة (GET/Range للتنزيل وPUT للرفع) من أصل Vercel.
8. بعد النشر: افتح `/dashboard` للإدارة و`/player` للتلفاز.

### المتغيرات

المتغيرات المطلوبة موضحة في `.env.example`. تشمل: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_S3_ENDPOINT`, `SUPABASE_S3_ACCESS_KEY_ID`, `SUPABASE_S3_SECRET_ACCESS_KEY`, `SUPABASE_S3_REGION`, `SIGNAGE_STORAGE_BUCKET`, `PAIRING_RATE_LIMIT_SALT`, و`CRON_SECRET`. الخدمة والمفاتيح الحساسة تُقرأ خادمياً فقط.

## المسارات

- `/login` — تسجيل دخول الإدارة.
- `/dashboard` — مؤشرات الشاشات والمحتوى.
- `/screens` — إنشاء الشاشة والاقتران والتعيين والأوامر.
- `/media` — رفع/بحث/فرز/معاينة/إعادة تسمية/حذف الوسائط.
- `/playlists` — تحرير وترتيب وسائط القوائم ومعاينتها وحفظ/نشر إصدار.
- `/schedule` — الجداول المحلية لكل شاشة.
- `/settings` و`/tv-setup` — حالة الخدمة وتعليمات الجهاز.
- `/player` — مشغل TV.

الاختبارات الحالية: 7 اختبارات unit باستخدام `fake-indexeddb` وطلبات شبكة مموّهة: حفظ/استعادة ملفات محلية، رفض تفعيل manifest ناقص، عدم تنزيل الفيديو غير المتغير في تحديث صورة فقط، الاحتفاظ بالقائمة العاملة عند انقطاع الشبكة/تلف ملف، تنظيف الملفات القديمة، واختيار الجدولة بما فيها عبور منتصف الليل. يجري GitHub Actions الفحوصات والبناء؛ لم تُختبر قاعدة Supabase حقيقية أو تلفاز فعلي.

## نموذج البيانات

الهجرة تنشئ: `profiles`, `organizations`, `screens`, `screen_credentials`, `pairing_codes`, `media`, `media_uploads`, `playlists`, `playlist_items`, `playlist_versions`, `schedule_entries`, `screen_heartbeats`, `sync_manifests`, `configuration_versions` و`pairing_rate_limits`. يربط رمز شاشة عالي الانتروبيا بصف اعتماد يحتفظ ببصمة SHA-256 فقط. رموز pairing أحادية الاستخدام وتنتهي خلال 15 دقيقة؛ تحديد المحاولات محفوظ بالخادم.

## حدود التشغيل التي يجب اعتمادها

- حصة IndexedDB وسلوك إخلائها وService Worker ودعم تشغيل `Blob` video تختلف باختلاف موديل LG ونسخة webOS والمتصفح. طلب التخزين الدائم best-effort وليس ضماناً من النظام؛ افحص الحالة/الحصة واختبر بعد إعادة تشغيل التلفاز.
- الاعتماد المخزّن يسمح بالتشغيل offline، لذلك إلغاء الشاشة/تعطيلها لا يمكن أن يوقفها عن بعد حتى تتصل مجدداً. هذا مقصود للحفاظ على التشغيل المحلي.
- إذا لم يسبق تنزيل محتوى صالح، أو مُسحت بيانات الموقع، فلن توجد ملفات محلية للتشغيل.
- الرفع المباشر متعدد الأجزاء يحتاج CORS و`PUT` صحيحين على واجهة S3 المتوافقة. التنزيل على التلفاز يعمل أيضاً عبر مسار التطبيق نفسه عند غياب CORS، لذا لا يعتمد التشغيل على إعداد CORS للتنزيل. يجب التحقق من إعداد التخزين وVercel داخل المشروع الحقيقي قبل قبول التشغيل الإنتاجي.

## فحص الإنتاج التلقائي

workflow «Production pairing E2E» (`.github/workflows/prod-e2e.yml`) يشغّل `scripts/prod-pairing-e2e.mjs` لدورة الاقتران و`scripts/prod-media-e2e.mjs` لمسار الوسائط الكامل (A–I: رفع، تخزين، قائمة، نشر، بيان، رابط موقّع، تنزيل Range مع SHA-256). المرحلتان تحتاجان جلسة إدارة عبر أسرار GitHub (`ADMIN_EMAIL`/`ADMIN_PASSWORD` أو `SUPABASE_SERVICE_ROLE_KEY`)، وتبلغ الفحوصات `SKIP` مع بيان الإمكانية الناقصة عند غيابها. التفاصيل في [دليل الإعداد](docs/ADMIN-SETUP.md).
- رفع multipart قابل للاستئناف من جلسة المتصفح الحالية عبر sessionStorage لمعرّف الجلسة واستعلام الأجزاء المكتملة. إعادة اختيار الملف نفسه بعد انقطاع الرفع تستأنف الأجزاء المكتملة.
- أحجام الأجزاء تُحسب في مكان واحد (`lib/shared.ts`: `uploadPartRange`) يستعمله المتصفح والخادم معاً، فلا يمكن أن يختلفا. المتصفح يقتطع الجزء بـ `Blob.slice(start, end)` حيث `end` غير شامل، ويقرأ طول الجزء من `Blob.size` نفسه ويُرسله في قائمة الأجزاء عند الإكمال. الخادم يتحقق من أن كل جزء مطابق للتقسيم ومن أن المجموع يساوي حجم الملف، ثم يقيس الكائن المُجمَّع بـ `HeadObject`. ملاحظة: `ListParts` في واجهة S3 لدى Supabase Storage لا يُرجع حقل `Size` إطلاقاً (يُرجع `PartNumber` و`ETag` و`LastModified` فقط)، لذلك لا يُعتمد عليه كمصدر لحجم الجزء؛ الاعتماد على `Size` الغائب كان يُفشل كل عملية إكمال رفع عند الجزء الأول برسالة «حجم أحد أجزاء الرفع غير صحيح».
- لا تشمل النسخة الحالية تحويل ترميز أو تطبيق webOS أصلياً أو مجموعات مناطق أو تعدد مناطق/مؤسسات فعلي أو لقطات شاشة عن بعد.
